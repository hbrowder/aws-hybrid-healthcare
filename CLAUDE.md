# AWS Hybrid Healthcare lab · rules for Claude Code

You are working on Hospital A of an EVE-NG lab that connects to Harold's AWS account.
A Palo Alto (hospital-a-fw) in EVE-NG builds two IPsec tunnels with BGP across the
internet to a Transit Gateway in AWS. The goal: the Linux client at 10.0.1.10 reaches
downrange-cloud-app at 10.100.11.10 and is seen there as 100.64.1.10.

Harold builds the EVE-NG nodes and does the console bootstrap. You run Terraform for the AWS
side under the gates below, and do the Palo Alto config and the checks through `lab.py`.

## You drive (Harold's standing instruction)

Harold wants you to take the wheel. Don't ask him to approve each step and don't explain

## Hard rules

1. **Only ever connect to management IPs in `inventory.json`** (today: 10.99.0.11). Never
   SSH, curl or ping anything else as a management target, including the EVE-NG host.
   If a task seems to need another host, stop and ask.
2. **Always use `lab.py`.** Do not hand-roll SSH sessions.
3. **Snapshot before you change anything:** `python lab.py snapshot hospital-a-fw pre-<task>-<date>`. PAN-OS allows 32 characters including `.xml`, so keep names short (e.g. `pre-rb-2026-11-01`).
4. **Load, diff, then commit: three separate steps.** Read the diff yourself before committing.
   Commit without asking only under the conditions in "You drive"; include the diff summary in your report.
5. **Never print, quote or store the pre-shared keys or credentials.** Don't open
   `configs/hospital-a-fw.set` in a way that shows its key lines, and never commit
   `configs/`, `terraform.tfvars` or any `.tfstate` to Git.
6. When the firewall rejects a set command, paste the exact error and stop. Don't guess
   another syntax and retry silently. **Expected exception:** the first six `delete` lines
   (factory virtual wire, zones, interfaces) may fail on a firewall that never had them, or on a re-load.
7. **AWS: only through Terraform in `terraform/`, gated as described in "Terraform and AWS" below.**
   Outside Terraform, AWS CLI is read-only: `aws sts get-caller-identity`, `aws ec2 describe-*`,
   `aws ec2 search-transit-gateway-routes`. Never create, change or delete AWS resources with the CLI.
8. Never touch the AT&T gateway or the EVE-NG host.

## Terraform and AWS

Profile `lab`, Region us-east-1. Every PowerShell session starts with:

```
$env:AWS_PROFILE = "lab"
aws sts get-caller-identity
```

If that fails with an expired or missing session, run `aws sso login --profile lab` and tell Harold
to finish the sign-in in his browser (MFA). Never handle his password or MFA code.

| Command | Gate |
|---|---|
| `terraform init`, `fmt`, `validate`, `plan`, `output` (not `-raw` on the PSK outputs), `show`, `state list`, `state show` | Run freely |
| `terraform apply` | Only after you have shown Harold the `plan` summary and he has said **"apply"** in chat. Always apply a saved plan: `terraform plan -out tfplan`, then `terraform apply tfplan`, so what runs is exactly what he approved |
| `terraform destroy` | Only after Harold says **"destroy"** in chat. Show him `terraform plan -destroy` first |
| `terraform import`, `state mv`/`rm`/`push`, `taint`, `force-unlock`, `-target`, `-replace` | Never. Stop and ask |

Before asking for "apply", show: the `Plan: X to add, Y to change, Z to destroy` line, and the name of
every resource it will **destroy or replace**. Anything other than "35 to add, 0 to change, 0 to destroy"
on a first build means stop and explain why.

`terraform.tfvars` holds `home_ip` and `alert_email` (never committed; keep `alert_email` when you refresh `home_ip`). Fill `home_ip` from `(Invoke-RestMethod https://checkip.amazonaws.com).Trim()`
and tell Harold the value. The firewall config comes from
`terraform output -raw palo_alto_config | Out-File -Encoding ascii ..\configs\hospital-a-fw.set`. Never print it.

## The build (once Harold has generated configs/hospital-a-fw.set)

```
python lab.py snapshot hospital-a-fw pre-aws-vpn
python lab.py load hospital-a-fw configs/hospital-a-fw.set
python lab.py diff hospital-a-fw          # read it; commit if only the expected deletes were rejected
python lab.py commit hospital-a-fw
```

Rollback: `python lab.py restore hospital-a-fw pre-aws-vpn`, then commit, and tell Harold you did.

After a rebuild (every new `terraform apply`), regenerate `configs/hospital-a-fw.set` and repeat the
build: the tunnel IPs and keys change each time.

## Checks, bottom up. Stop at the first failure.

```
python lab.py show hospital-a-fw "show interface ethernet1/1"          # 192.168.1.x from DHCP
python lab.py show hospital-a-fw "show vpn ike-sa"                     # aws-t1 and aws-t2 established
python lab.py show hospital-a-fw "show vpn ipsec-sa"                   # both tunnels have SAs
python lab.py show hospital-a-fw "show routing protocol bgp summary"   # both peers Established
python lab.py show hospital-a-fw "show routing route type bgp"         # 10.100.0.0/16 active via tunnel.1 (tunnel.2 is the standby path; no ECMP)
```

AWS side (PowerShell, from terraform/):
```
aws ec2 describe-vpn-connections --vpn-connection-ids (terraform output -raw vpn_connection_id) --query "VpnConnections[0].VgwTelemetry[].{IP:OutsideIpAddress,Status:Status,Routes:AcceptedRouteCount}" --output table
aws ec2 search-transit-gateway-routes --transit-gateway-route-table-id (terraform output -raw rt_vendor_id) --filters Name=type,Values=propagated
```
Expected: both tunnels UP with 1 accepted route each; rt-downrange-cloud shows 100.64.1.0/24.

AWS monitoring checks (read-only, from terraform/; monitoring.tf builds these):
```
aws cloudwatch describe-alarms --alarm-name-prefix hospital-a- --query "MetricAlarms[].{Alarm:AlarmName,State:StateValue}" --output table
aws logs filter-log-events --log-group-name /downrange-cloud/vpc-flow --filter-pattern "100.64.1" --max-items 5 --query "events[].message"
aws logs filter-log-events --log-group-name /downrange-cloud/vpn-hospital-a --max-items 5 --query "events[].message"
aws networkmanager get-transit-gateway-registrations --region us-west-2 --global-network-id <from terraform state show> --query "TransitGatewayRegistrations[].State.Code"
aws sns list-subscriptions-by-topic --topic-arn <topic arn> --query "Subscriptions[].SubscriptionArn"
```
Expected: both alarms OK once the tunnels are up; flow-log lines for 100.64.1.x to 10.100.11.10 after a client
test; IKE lines in the VPN log; registration AVAILABLE; subscription not "PendingConfirmation" (if it is, Harold
must click the email link). In your report, give Harold the `watch_*` outputs so he can open each view.

The client tests (`ping 10.100.11.10`, `curl http://10.100.11.10:8080` showing
